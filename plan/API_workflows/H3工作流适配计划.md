# oh-my-minimaxh3-director × bak 01 工作流适配计划

> 日期：2026-09-22
> 背景：硬件受限，只能用 `omy/` 下已验证可跑的 GGUF 工作流，不能改用内置模板
> 目标：让 Director 管线把 omy 工作流当作模板正常生成/提交/监控，暂不启用 Turbo LoRA

---

## 一、现状盘点

`omy/` 共 5 个工作流，分成两类：

| 文件 | 类型 | 核心节点 | 是否纳入 H3 管线 |
|---|---|---|---|
| `minimax_h3_t2v-gguf-api.json` | H3 文本转视频 | `MiniMaxH3ImageToVideo` | ✅ |
| `minimax_h3_i2v-gguf-api.json` | H3 首尾帧转视频 | `MiniMaxH3ImageToVideo` | ✅ |
| `minimax_h3_ref2v-gguf-api.json` | H3 参考图/视频/音频转视频 | `MiniMaxH3ReferenceToVideo` | ✅ |
| `Krea2_t2i_20260818_API.json` | Krea2 文生图 | — | ❌ 排除 |
| `krea2_T2I_CharSheetV1_API.json` | Krea2 角色卡 | — | ❌ 排除 |

> Krea2 两个是图像工作流，不属于 Director 的 H3 视频路由范围，本计划不处理。

### 模型与节点依赖（H3 三者一致）

- UNet：`UnetLoaderGGUF` → `minimax_h3_fl2va_pruned-Q4_K_M.gguf`（ref2v 用 `minimax_h3_ref2va_pruned-Q4_K_M.gguf`）
- CLIP：`CCTechClipProjLoader` → `qwen3-vl-4b-heretic-Q4_K_M.gguf` + `projection: mmh3-4b-ClipProj-v3.1.safetensors`
- VAE：`minimax_h3_video_vae_fp16` / `minimax_h3_audio_vae_fp32`
- 采样链：`KSamplerSelect` + `BasicScheduler` + `SamplerCustomAdvanced` + `BasicGuider` + `RandomNoise`（标准采样，**不含 Turbo**）
- 时长：`ComfyMathExpression` + `PrimitiveFloat`
- 分辨率：`ResolutionSelector`
- 前处理：`ForceUnloadBeforeDecode`

> 与内置模板关键差别：内置 t2v 用 `MiniMaxH3TurboLoRA`/`MiniMaxH3TurboSampler`（4 步 turbo）；本套是标准 20 步、无 turbo——保持现状，不启用。

## 二、与 Director 参数注入点逐项比对

`build_workflows.py` 按 class_type 覆盖参数（不写死节点 ID）。对照结果：

| 注入点（class_type） | 字段 | omy t2v | omy i2v | omy ref2v |
|---|---|---|---|---|
| `PrimitiveStringMultiline` | `value`（提示词） | ✅ 300 | ✅ 300 | ✅ 300 |
| `ComfyMathExpression` + `PrimitiveFloat` | 时长（秒） | ✅ 134 | ✅ 135 | ✅ 135 |
| `BasicScheduler` | `steps` / `scheduler` | ✅ 124 | ✅ 128 | ✅ 128 |
| `KSamplerSelect` | `sampler_name`（可选） | ✅ 123 | ✅ 127 | ✅ 127 |
| `RandomNoise` | `noise_seed` | ✅ 127 | ✅ 131 | ✅ 131 |
| `ResolutionSelector` | `aspect_ratio`/`megapixels`/`multiple` | ✅ 115 | ✅ 115 | ✅ 115 |
| `SaveVideo` | `filename_prefix` | ✅ 92 | ✅ 92 | ✅ 92 |
| `LoadImage` | `image`（参考图/首尾帧） | —（无图，正常） | ✅ 114/141 | ✅ 149 |
| `LoadVideo` | `file`（参考视频） | — | — | ⚠️ 156 |
| `LoadAudio` | `audio`（参考音频） | — | — | ⚠️ 153 |

**结论：3 个工作流的参数注入点全部兼容 Director 现有能力（t2v/i2v 天然兼容，ref2v 仅缺视频/音频资产）。**

> **补充（2026-09-30 12:06 实测后追加）**：上表 `ResolutionSelector`（节点 115）与 `ComfyMathExpression` + `PrimitiveFloat`（时长）这两个注入点，**改完值之后输出并非所见即所得**，注入方必须知道两条换算规则：
>
> 1. **分辨率**：`megapixels` 是 1024 基准的浮点滑块（0.1~16.0，步进 0.1），且按 `multiple`（本项目设 32）取整会漂移 —— 0.5 实际是 0.522 MP，0.9 实际是 0.942 MP。**完整换算表（0.1~1.2 全部档位 × 8 种宽高比）见主计划 `plan\ComfyUI_MiniMaxH3_AMD_7900XTX_Plan.md` §11.10.1**。另经源码核查确认：目标画布**无任何上限钳制**（§11.10.2），填 1.0 就真跑 1376×768，不报错也不裁剪。
> 2. **时长**：传秒数后先 `max(5, round(秒 × 24))`，再**向上**对齐到 `17k+5` 网格，**静默取整**。传 4 秒 → 107 帧 = 4.458 s（**低于训练下限 124 帧，越界**）；要留在范围内最小输入是 4.5 秒。详见 §11.10.3。

## 三、需要修改的点

### A. 工作流文件（`omy/` 下 3 个 H3 文件）

文件本身**无需结构性改写**——已经满足 Director 的 class_type 注入点。可选的清理（非阻塞）：

1. 确认 `SaveVideo.filename_prefix` 会被 Director 覆盖为 `<项目>/<模式>/seg_XX`，默认值不影响
2. 无需 Turbo 节点，保持现状即符合"先不使用 Turbo LoRA"

### B. Director 脚本扩展（3 处，都是小改）

#### B1. `scripts/scan_workflows.py` — 识别 GGUF 加载器

扩展 `LOADER_FIELDS`，否则扫描结果 `models` 为空、`turbo` 恒 False、工作流显示"模型未知"：

```python
LOADER_FIELDS = {
    "UNETLoader": "unet_name",
    "CLIPLoader": "clip_name",
    "VAELoader": "vae_name",
    "LoraLoaderBypassModelOnly": "lora_name",
    "MiniMaxH3TurboLoRA": "lora_name",
    "UnetLoaderGGUF": "unet_name",        # 新增
    "CCTechClipProjLoader": "clip_name",  # 新增
    "CLIPLoaderGGUF": "clip_name",        # 新增（Krea2 若将来复用）
}
```

#### B2. `scripts/submit_jobs.py` — 上传视频/音频参考资产

当前 `upload_workflow_assets` 只处理 `LoadImage`（`/upload/image`）。ref2v 含 `LoadVideo`（`/upload/video`）与 `LoadAudio`（`/upload/audio`），需扩展，否则远程必报"找不到文件"：

- 遍历节点按 class_type 分派：
  - `LoadImage` → `upload_image`（现有逻辑，含路径改写）
  - `LoadVideo` → `upload_video`（`POST /upload/video`，同 `type=input` + `subfolder=<项目>/refs`），改写 `inputs.file`
  - `LoadAudio` → `upload_audio`（`POST /upload/audio`，同上），改写 `inputs.audio`
- 重试/幂等语义与现有 imagem 保持一致（`overwrite=true`、同批缓存）

#### B3. `scripts/build_workflows.py` — ref2v 的视频/音频参考映射

ref2v 有 `get` 3 个参考输入：`ref_images.ref_image_0`（→`LoadImage`）、`ref_videos.ref_video_0`（→`LoadVideo`）、`ref_audios.ref_audio_0`（→`LoadAudio`）。

- 方案：`apply_refs` 增加对 `LoadVideo`/`LoadAudio` 的处理，从 segment 字段取值：
  - `segment.refs[0]` → `LoadImage.image`（现有）
  - `segment.ref_video` → `LoadVideo.file`（新增字段）
  - `segment.ref_audio` → `LoadAudio.audio`（新增字段）
- 若 segment 未提供 ref_video/ref_audio，保留模板内已有默认文件名（不强制报错）→ 维持单一参考图即可跑通
- `workflow-routing.md` 同步补充字段说明

### C. 模板接入方式（二选一）

- **方式 1（推荐，临时）**：`storyboard.json` 的 `meta.workflow_map` 指向 omy 文件绝对路径：
  ```json
  "workflow_map": {
    "t2v": "D:/localAI/ComfyUI-last/plan/API_workflows/omy/minimax_h3_t2v-gguf-api.json",
    "i2v": ".../minimax_h3_i2v-gguf-api.json",
    "ref2va": ".../minimax_h3_ref2v-gguf-api.json"
  }
  ```
- **方式 2（复用）**：把 3 个文件拷到 Director 自定义模板目录，`pipeline-config.json` 设 `templates_dir`

> `build_workflows.py` 的 `load_template` 已支持绝对/相对路径 + 模板名，且 UI 格式会拒绝。ova 文件均为 API 格式，直接可用。

## 五、风险与取舍

| 风险 | 说明 | 对策 |
|---|---|---|
| 远端 ComfyUI 未装 GGUF 插件 | `UnetLoaderGGUF` 会解析失败 | 提交前 /system_stats + object_info 核对节点存在 |
| 远端无参考视频/音频文件 | `LoadVideo`/`LoadAudio` 上传是新增能力 | B2 确保上传 + 提交后校验 history 报错 |
| 模型文件路径（远端 input 目录） | GGUF 需在远端 `input/checkpoints` 或 models 目录存在 | 用 `object_info` 核对模型名 |
| ref2v 无 ref_video/ref_audio 时 | 保底用默认文件名可能不存在 | 提交前提示用户在 storyboard 提供或远端预置 |

## 六、本计划不做的事

- ❌ 不处理 Krea2 两个图像工作流
- ❌ 不重写工作流结构与节点关系（文件中 class_type 已兼容）
