## 2. 测试设计（为什么可信）

### 2.1 唯一变量 = 启动 flag

两臂 ComfyUI 启动参数集合差异经程序化核对，**仅 `--use-ck-attention` 一项**：

```
A_ck   --windows-standalone-build --enable-dynamic-vram --disable-pinned-memory
       --fp16-intermediates --disable-smart-memory --reserve-vram --disable-api-nodes
       --cache-none --use-ck-attention

B_nock --windows-standalone-build --enable-dynamic-vram --disable-pinned-memory
       --disable-smart-memory --reserve-vram --disable-api-nodes --cache-none
       --fp16-intermediates
```

（`--fp16-intermediates` 位置不同但 argparse 无视顺序。证据：`arm_flags.json`）

### 2.2 噪声地板 = 精确零（可靠性的地基）

`ck` 臂**同参数连跑两次**（`ck_r1` / `ck_r2`，39 帧）：

```
比对帧数        : 39
像素 sha256 全等 : 39  -> 位级一致
mad / r / SSIM  : 0.0000 / 1.00000000 / 1.00000000
```

**这一步是全套结论的前提**：H3 生成是位级确定的，噪声地板为零，因此后续任何差异都 **100% 可归因** 于 attention 后端，不含采样随机性。

> ⚠️ 踩坑记录：初版比对工具用 PNG **文件字节**做 sha256，而同内容不同 PNG 编码元数据会导致字节不同 → 把「完全确定性」误判成「39 帧全有差异」。已改为哈希**像素数组**。同理初版 PNG 序列前缀匹配写错（`ck_r1_00001_` 当成前缀），只比到 1 帧就宣布「39/39 通过」——**结论是假阳性，已作废重做**。

### 2.3 无损比对（不引入二次有损）

`gen_h3_multisegment-8b.py` 末尾 `concat_segments()` **无论几段都会 libx264 重编码（CRF 23）**，会在生成差异之上叠一层有损压缩。

故本次用独立探针 `gen_h3_ck_ab.py`（**只增，未改动 `plan\bat\` 内任何现有脚本**）：复刻完全相同的图（`UnetLoaderGGUF` / `CCTechClipProjLoader` / `MiniMaxH3ImageToVideo` / `ForceUnloadBeforeDecode`×2 / `BasicGuider` / `BasicScheduler(simple)` / `KSamplerSelect(res_multistep)` / `SamplerCustomAdvanced` / `CreateVideo`），**额外挂一个 `SaveImage`** 把 `VAEDecode` 输出的帧以**无损 PNG** 落盘。

比对输入 = 解码器输出本身，不含任何二次有损。

### 2.4 量具双路径自检

`compare_frames.py` 上线前先用已知答案校准：

| 自检 | 输入 | 期望 | 实测 |
|---|---|---|---|
| 恒等 | 同一 mp4 两次 | 位级全等 | 107/107 全等 ✅ |
| 灵敏度 | 原片 vs 亮度 +1/255 | 可测出微小差 | mad=1.23 / r=0.99968 / SSIM=0.9931 ✅ |

**顺带得到标尺**：亮度 +1/255（≈0.4% 亮度）即产生 mad=1.23。本实测 mad=0.91 **小于**该标尺。

## 4. 机制解读

ck 的 int8 量化让每次 attention 的数值发生微小改变。扩散采样是确定性的，但这 20 步里微小的数值扰动会**混沌放大**，最终落到**另一个同样合法的采样结果**上——而不是「同一张图加噪声」。

证据支持这个解读：
- 差异集中在**边缘与细节纹理**（人物轮廓、发丝、织物），即两个合法样本最容易分岔的地方
- 误差**高频为主**（量化噪声特征），不是低频块状（结构破坏特征）
- ck 侧**一致更锐 +5.5%**（124 帧无例外）——损坏不会带来系统性锐度提升
- 步数增加 → 差异收敛（采样器自校正）

「两个不同的合法样本」也解释了为何 `mad` 沿时间轴起伏（0.74–1.16）而无尖峰。

### 本次修掉的两个工具缺陷（复用时注意）

1. sha256 必须哈希**像素数组**，不能哈希 PNG 文件字节（同内容不同编码元数据 → 字节不同）
